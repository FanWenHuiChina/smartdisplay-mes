# SmartDisplay MES API 版本与弃用策略

生成时间：2026-06-27

## 1. 版本化方式：URI 前缀

所有业务接口统一走 `/api/v1` 前缀（`server.servlet.context-path=/api` + 控制器 `@RequestMapping("/v1")`）。选 **URI 版本化** 而非 Header/参数版本化的理由：

- 直观、可缓存、可在浏览器/Swagger/curl 直接区分，演示与排障友好；
- 与 Nginx 反代、网关路由、灰度分流天然契合（按路径前缀切流量）；
- 代价是同一资源多版本时路径会重复——在单基地试点的规模下可接受。

> Actuator 管理端点（`/api/actuator/**`）不属于业务 API，不纳入 `/v1` 版本治理。

## 2. 版本并存与演进

- **v1 = 稳定契约**。已发布的 `/v1` 端点遵循"只增不破"：只新增可选字段/端点，不删除字段、不改字段语义、不收紧已有约束。
- **破坏性变更 → 升 v2**。需要不兼容变更（删字段、改类型/语义、改鉴权模型）时，新增 `/api/v2`，与 `/v1` 并存一个公告期，前端与外部集成方按节奏迁移。
- **分组文档**。SpringDoc/Knife4j 已按 `pathsToMatch=/v1/**` 分出 `pilot-v1` 分组；新增 v2 时再分一组，文档层面天然隔离。

## 3. 弃用流程（Deprecation）

1. **标注**：被弃用端点在 OpenAPI 上标 `deprecated=true`（`@Operation(deprecated = true)`），文档显式划线提示。
2. **响应头公告**：返回 `Deprecation: true` 与 `Sunset: <RFC1123 下线日期>` 响应头（参考 RFC 8594），并在 `Link` 头给出替代端点。
3. **公告期**：至少保留一个迭代周期，期间双版本并存、监控旧端点调用量。
4. **下线**：调用量归零且迁移完成后移除旧端点；迁移说明随版本说明发布。

## 4. 向后兼容约定（v1 内）

| 允许（非破坏） | 不允许（破坏，需升版本） |
|---|---|
| 新增可选请求字段 | 删除/重命名已有字段 |
| 响应新增字段 | 改变已有字段类型/语义 |
| 新增端点 | 收紧校验（如把可选改必填） |
| 枚举新增取值（消费方需容错未知值） | 删除枚举取值 |
| 放宽校验 | 改变错误码/鉴权语义 |

统一响应包装 `Result{code,message,data,timestamp}` 与标准错误码（400/401/403/500）属于跨版本稳定契约，不随业务版本变动。

## 5. 当前状态与扩展点

- 当前仅 `/api/v1`，无已弃用端点。
- 上述 `Deprecation`/`Sunset` 响应头与 `@Operation(deprecated)` 为预留落点，真正出现 v2 迁移时再启用，不提前引入未使用代码。
